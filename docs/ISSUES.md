## 网页预览与60FPS客户端（2026-10-22补充）

- 网页此前每1.5秒更新图片、桥接每秒采集1张，故网页观感不足1FPS，不能用它推断客户端渲染或服务器tick。按用户要求将客户端上限从120改为60，网页与采集目标设为20FPS；两端8区块、服务器6GiB和客户端8GiB保持。
- 图片刷新独立于状态轮询和模型推理；服务返回同一图片文件的时间戳，页面按新帧去重，预先解码后换图，顺序请求限制积压，释放旧Blob URL。界面分别显示游戏、采集和网页实际帧率及最近画面年龄，失败显示原因。
- 60/20配置与AI同时运行26次采样：客户端48.7–61.1FPS、采集中位16.9FPS，网页实际观察17.1FPS、画面年龄21–33ms；服务器20TPS、总平均tick1.855ms，可用内存最低10.15GiB、总显存峰值4263MiB。20为目标而非实测保证。
- 同配置重跑verify_mining.py通过，真实取得1块泥土，全部释放保护再次通过。模型真实决策回执中已有54个包进入持续挖掘；这不证明其选对方块或取得了有用掉落。
- 快速重启还发现旧客户端的500ms状态文件可能使新进程过早通过就绪检查。新客户端启动前删除旧生成状态，复用运行中的客户端则保留；新增回归测试，现共24项通过。

## 连续挖掘与游戏资源（2026-10-22补充）

- 官方200ms是动作决策单位，但原执行器在每包结束释放全部按键，推理间隙会中断挖掘。现仅允许6步全LB、同一目标且没有混合右键/中键的游戏内左键延续，其他键仍释放；目标、所选槽位、界面或连接变化、控制epoch变化、心跳过期及10秒上限均结束保持。
- 监看服务增加独立250ms心跳，客户端读取1500ms有效期和控制epoch；重启使用新的epoch，暂停及命令立即发布控制变化，命令执行等待普通动作和长按均释放。完成回执标记是否取消及是否继续挖掘，取消动作不算完整执行。
- 对照验收中3次200ms左键各间隔1.4秒均未破坏泥土；一次延续长按约0.85秒后破坏，实际拾取1块泥土。暂停、停止心跳、改变目标和10秒上限均释放，实际虚拟左键轮询也确认释放。测试平台清理、位置恢复；没有声称模型自主完成。
- 原桌面服务器脚本为-Xms6G/-Xmx6G、view-distance=8，而初始实验降为1G/4G和4区块。现恢复服务器6G/6G及8区块；客户端改为2G/8G、8区块、120FPS与精细画质，资源与模型配置分开。原HMCL实例options仅有lang，不能据此声称恢复了其实际历史运行参数。
- 资源恢复后实际采样46次，客户端106.3–120.2FPS，服务器4次均20TPS、总平均tick1.853–1.916ms；最低可用内存9.48GiB、总显存峰值4022MiB。静止时渲染队列Q:0+0i；没有证据支持当时的加载观感是服务器掉TPS所致。视距小来自配置，网页刷新低另行处理。

## 提示词与续玩记忆（2026-10-22补充）

- 重启进程会丢失画面历史，单靠服务端存档不能让模型记得目标和约定。新增私有memory/文件与观察台编辑入口；每轮把精简记录加入原生游戏提示，保留实际注入文本和哈希，停止前保存快照，冷启动读回。
- S1是动作策略，不能假设它具备可靠的自由文本总结能力。总结请求与游戏请求串行，使用独立JSON约束，只允许选择下一步建议和未知项；Markdown由程序生成。玩家、坐标、生命、背包和物品变化由客户端采集，任务完成固定标为未验证，避免把目标或模型猜测变成完成记录。
- 背包读取失败与空背包分开处理；换槽不算获得/丢失物品，数量按注册物品ID汇总。记录不覆盖箱子等外部容器，也没有自动绑定其他世界；换世界需另建记忆。
- 保存使用临时文件、刷盘和替换；编辑前及总结后归档，编辑冲突提示重读，页面轮询不覆盖未保存的内容。memory/排除于Git和源码包，完整私有备份包含它。

## 2026-10-22

- 原版 GTNH 服务器启动脚本固定 6 GiB 且退出后自动重启。测试副本改用单次受控启动，堆上限 4 GiB；绑定回环地址，便于监测并减少同机内存竞争。
- 原版客户端依赖清单包含继承的重复库。直接拼接会优先载入 Guava 15，导致 `CharSource.readLines` 缺失，进而让 Forge AccessTransformer 加载失败，出现多个模组 IllegalAccessError。启动器按 HMCL 语义以同名库最后版本覆盖（Guava 17），保留完整整合包。
- 旧版 `jinput-platform` 是仅提供原生库的依赖，没有普通 jar；启动器单独提取 Linux natives。
- 模型预算：原始 9B BF16 约 18.8 GB，无法给双 Java 进程留下足够余量；主方案采用对应检查点 Q4_K_M 与独立视觉投影。小模型官方文件作为格式与回退验证资料。
- 原始桌面 GTNH 和 HMCL 文件只读复用；实验发生于当前项目的 `instances/` 副本。
- 桥接采用客户端模组内的截图与按键绑定，不向整个桌面发送键鼠事件。
- GTNH 主菜单由 Custom Main Menu 替换成 `GuiCustom`；自动连接识别该菜单，并处理断线重连。
- 直接构造原版 `GuiConnecting` 绕过了 Forge 的握手初始化，导致 `playClientBlock` 空指针。改用 `FMLClientHandler.connectToServerAtStartup`，保留 Forge 正常握手链路。
- 背包/任务书界面需要将模型鼠标位移映射为 GUI 坐标并派发界面点击、释放、拖动与键盘事件；仅设置游戏 KeyBinding 无法完成 GUI 操作。
- mradermacher 9B-S1 Q4_K_M 转换文件包含 32 层主权重（blk.0–31），却声明 `qwen35.block_count=33`、`nextn_predict_layers=1`，没有第33层 MTP 张量。llama.cpp 报 `blk.32.attn_norm.weight not found`。保留原文件，在兼容副本中将两个元数据值改为 32 / 0；逐字节哈希验证所有 tensor data 不变，记录 `gguf-normalization.json`。这没有补造预测层或改写主模型权重。
- lwjgl3ify 的 `Mouse.setCursorPosition` 在桥接反射路径得到空 GLFW 窗口句柄。GUI 点击坐标改由桥接直接派发，并用客户端内的逻辑鼠标位置保持模型观测一致；不依赖操作系统鼠标输入。
- 修复 GGUF 主层数后，原有 recurrent_layers 数组仍长33。兼容副本保留该数组为未使用元数据，使用原文件的 full_attention_interval=4 推导32层模式，并验证它与原数组前32项完全一致；所有张量字节不变。
- 当前 llama.cpp 的媒体占位符含每次启动生成的随机部分，不能照文档示例硬编码 `<__media__>`。客户端从 `/props.media_marker` 获取实际值，否则报图像数量与标记数量不匹配。
- 原生 completion 接口会剥离 stop 字符串，当前版本通过 `stop_type=word`、`stopping_word` 返回终止原因。只有确认实际命中 `<|action_end|>` 时才恢复末尾标签；不能按另一个接口版本的 `stopped_word` 字段判断。
- BetterQuesting 自定义按钮不能只直接调用 GuiScreen.mouseClicked：改为向 lwjgl3ify 的客户端本地鼠标事件队列派发按下/释放；已实测任务书主页的 Quests 按钮进入 GuiQuestLines，书签按钮进入 GuiBookmarks。
- 单个33ms点击可能在下一帧前过期。包接收时立即执行第一子步骤，后续子步骤再按渲染事件计时。
- 监看进程重启时恢复已完成决策编号，不覆盖旧截图与输出；后续每个动作还记录实际客户端确认和执行后状态。
- 首批模型输出存在物品误识别，例如将任务书说成斧头；提示加入实际起始物品和由本机GTNH任务配置提取的数量要求。这是上下文适配，并没有通过训练消除误识别。
## 后台虚拟输入与隐藏窗口（2026-10-22补充）

原桥接已避免操作桌面鼠标，但真实 GLFW 回调、硬件按键轮询和窗口失焦仍可能影响测试客户端。新增只随专用客户端加载的 Java agent，在 lwjgl3ify 输入边界拦截真实事件，轮询只返回桥接持有的虚拟按键。GUI虚拟事件使用限定调用范围放行；共享状态由bootstrap类加载器加载，避免RFB与Forge持有两份状态。

逻辑鼠标抓取和坐标修改保留在客户端内，不再调用桌面抓取/移动；游戏调度使用虚拟焦点。创建 GLFW 窗口时设为不可见、不聚焦，保留 OpenGL 渲染上下文，截图继续送往8790。运行状态额外报告真实可见性、真实焦点、光标模式与拦截计数。

实际客户端验收：5种硬件回调被拦截，虚拟轮询/点击通过，无焦点隐藏状态下移动、转头、背包开关和截图变化均通过。当前不需要安装虚拟桌面，也不修改系统键鼠设置。

## 服务器命令窗口与游戏规则（2026-10-22补充）

- 新增 Minecraft 命令窗口和快捷按钮。使用回环RCON取得对应命令的实际回显，不通过操作系统终端执行用户输入。随机凭证仅存放在私有测试服务器属性文件；输入限制单行，HTTP接口检查来源、主机和JSON内容类型。
- Minecraft 1.7.10 RCON会关闭含合并请求包的连接。实测独立认证、发送一条命令并先读取首个回复，然后发送响应分界探针才兼容；后续继续拼接同编号输出，分界探针回显不进入用户结果。回归测试覆盖分片、UTF-8跨包、身份验证失败及断线。
- `server-settings.json`定义和平难度、非极限模式与死亡不掉落。启动前配置属性，观察服务检测新服务端进程后应用规则、读取keepInventory并save-all；已实测返回true，保存后的World/level.dat亦包含true。
- 手动命令默认暂停模型操作、清空截图历史并递增场景版本；正在推理的旧动作即使完成也不再执行。第69轮实际记录了旧动作丢弃，位置未受其W动作影响。暂停/恢复状态持久保存。
- UI命令与快速按钮已实际验证：在线玩家包含GameScalingBot，手动`/gamerule keepInventory`返回true，白天返回时间1000，晴天返回天气修改回显。

## 一键冷启动与完全停止（2026-10-22补充）

- 根目录提供可执行start.sh、stop.sh，以脚本所在路径定位工作区；启动无需激活虚拟环境，停止仅依赖系统Python。原生命周期工具不等待实际就绪，新编排器验证RCON、模型健康、客户端连接、输入隔离和服务器规则后才开放自动操作。
- 原PID识别只凭工作目录或命令行包含项目路径，且依赖PID文件。现改为扫描实际进程并核对精确角色参数：服务器工作目录及入口、客户端桥接参数、模型文件与服务参数、观察台Python入口。实际移走四个PID文件后重复启动成功恢复原PID，没有创建重复服务。
- 使用启停锁防止同时启动；stop.sh可请求取消尚未完成的启动。失败时清理本次新增服务，预先已有服务继续保留。控制状态改变使在途旧动作失效。
- 完全停止先关闭观察台/客户端，再经服务器控制台save-all、stop保存世界，退出模型并核对进程及端口。普通程序超时可清理，服务器额外等待JVM关闭；强制结束卡死服务器需要显式--force。
- 模型SHA256校验以文件大小、修改/元数据时间及预期摘要缓存；首次或文件变化时重新计算。首次缺少独立实例、项目环境、桥接或任务上下文时自动补齐，对现有模型缺失或端口被其他进程占用则报告具体原因。

## 2B全显卡切换（2026-10-22补充）

- 官方2B-S1 BF16权重已在此前完整备份中。使用hf按固定版本验证本地文件，源safetensors SHA256与上游一致。配置声明一个MTP层但没有MTP张量；本次转换直接使用llama.cpp的--no-nextn生成24层语言模型，未沿用9B第三方转换的修复流程。
- 本机转换得到语言F16和视觉F16，再量化语言为Q4_K_M。两个运行文件分别1560461088和668227200字节；独立来源、转换及校验清单已保存，可运行prepare_2b.py复现。
- 默认全层卸载仍会留下约272.81MiB的CPU_Mapped词嵌入权重。2B全GPU配置额外使用--override-tensor '.*=CUDA0'，实测CUDA0语言权重1477.72MiB且无CPU_Mapped模型缓冲，25/25层、视觉CLIP、96MiB KV和19.27MiB循环缓存均在CUDA0。程序、输入输出及映射仍会使用主存。
- 启动/停止的进程识别同时支持2B和9B。启动脚本新增--model 2b/9b并记住选择，首次默认2B；观察台从实际启动信息读取模型名和GPU模式，每个新决策也保存对应模型信息。9B文件及原配置保留。
- 三组旧9B截图连同各自五帧历史回放：2B全GPU中位1.274秒，旧9B/8层GPU记录中位17.736秒，约13.93倍；显存采样峰值3943MiB、最低空闲3834MiB。2B回放使用seed123，历史9B采样无固定种子；结果只比较这两种本机配置的速度，不推导GTNH任务能力。
- 已在当前隐藏客户端完成至少75轮实际执行确认，推理中位1.290秒，观察到行走和背包界面。尚未据此确认完成首项任务或科技推进。
- 连续运行还暴露了llama.cpp默认8GiB旧提示主存缓存的代价：2B模型进程RSS会升至约12GiB。最终配置关闭该缓存（--cache-ram 0），上下文检查点从32限制为2，活动KV/循环缓存仍在GPU。重启后45秒实际连续17个新决策中，模型RSS峰值1060MiB、系统可用内存最低15.99GiB，回放仍约1.27秒。此为短时验证，未声称数小时内存峰值。

## v0.2 非托管服务器接入

完整向导实测发现manage.start构建所有角色参数时会提前读取server.jar，导致合法的非托管实例无法启动显示/客户端。改为只为实际启动角色构建服务端参数，并加入无server.jar的非托管客户端回归测试。接入模式的网页命令按钮保持禁用，原服设置与进程保持原有管理方式。
