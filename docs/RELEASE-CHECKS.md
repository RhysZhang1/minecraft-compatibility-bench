# 发布前审查（2026-10-23）

本次审查以从GitHub克隆后的安装流程为目标；模型配置和已验证的四个原版版本保持不变。

## 修复内容

- Java安装重试重新核验完整清单，避免仅看到bin/java就跳过缺失库。
- 原版安装向导将实际Java路径同步登记给独立服务器入口；检测显示当前实例Java。
- 服务器安装在带版本标记的临时目录进行，失败可重试，完成后才发布最终目录。无效EULA来源在创建目录前报错；启动缺少接受记录时提前提示。
- 复用已登记服务器时展示真实路径/端口，不静默使用用户新填的另一目录。配置期间要求游戏停止。
- 2B转换使用临时输出，成功后原子发布；9B元数据处理先校验原始模型SHA256，在临时副本验证张量不变后才发布。
- 停止时暂停文件写入失败也继续收回进程；登记的独立服务器丢失PID文件时按目录和命令找回。一个独立服务器停止失败不跳过其他服务器。
- 虚拟显示的主进程与合法publish辅助进程作为同一服务复用，修复重复start.sh误报进程重复的问题。该问题通过真实运行发现，再加入回归检查。

## 验证范围

- 49项自动化测试，包含安装中断重试、失败转换不发布成品、世界隔离、控制文件故障、精确进程身份、动作与记忆事实边界。恢复时也会重写独立服务器入口，避免指向备份前的旧项目。
- 独立临时Python3.11环境实际安装运行和下载依赖；转换依赖另做解析验证。
- Shell语法、Python编译、全新源码目录中的向导、doctor与入口帮助。
- 真实服务验收：丢失PID文件后完整停止、重复停止、端口占用且保留占用进程、启动中途取消并清理、从/tmp冷启动、重复启动复用相同PID。
- 旧版四版本基础操作记录仍见VANILLA-VALIDATION.md；本次没有再次声称完整重测四个游戏版本，也未重跑模型训练/长期任务评测。
- 历史Git blob扫描检查私有目录、超大文件和常见密钥格式。此类扫描不能替代用户对任意私人内容的审阅。

CI只验证源码、依赖、语法和自动化测试，不在GitHub运行器上下载游戏/模型，不声称CI执行了GPU或真实游戏测试。游戏日志、测试世界和截图证据保留在本地runtime/validation/。
