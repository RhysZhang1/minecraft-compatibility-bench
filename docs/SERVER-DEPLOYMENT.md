# 给只有MC服务端的电脑添加AI

目标是由向导完成“检测 → 资源推荐 → 选择接入 → 环境准备 → 独立记忆 → 暂停启动”。MC视觉客户端仍需在后台运行，详见HEADLESS.md。

## 只读检测

```bash
./setup.sh --inspect-server /srv/minecraft
# 老服务端无可识别元数据时明确指定基础版本
./setup.sh --inspect-server /srv/minecraft --version 1.7.10
# 在指定目录下查找两层，不扫描整块磁盘
python3 scripts/deploy_server.py --scan /srv
```

检测仅读取清单、JAR内版本信息、server.properties与已知启动参数，探测本机游戏端口和匹配目录的Java进程；不会执行未知启动脚本或JAR。报告不显示RCON密码，只报告是否配置。

会检查：系统/架构/WSL，内存及cgroup可用上限，空闲磁盘、CPU、NVIDIA可用显存、KWin及工具/运行库；游戏版本、加载器、端口、online-mode、白名单、世界是否存在、视距、难度、RCON和-Xmx设置。

## 模型推荐

目前自动下载/准备仅覆盖2B和9B。先预留服务器堆增长、原版客户端4GiB（模组客户端8GiB）和系统2GiB，再计算模型内存预算；不会降低原服已配置堆上限来让模型勉强挤进去。

2B模型额外预算约4GiB内存，9B约10GiB；GPU估算分别要求当前空闲显存约6.5GiB/12GiB，已包含视觉编码器、上下文/计算和游戏渲染余量。足够宽裕时可推荐9B GPU；否则优先2B，显存不足时推荐CPU。剩余内存不足则停止自动添加。

这些是保守启发式预算，不是实际速度、准确率或不崩溃保证。空闲资源会变化，向导在保存配置前再次检测。CPU推理可能很慢，AMD/Vulkan推理和27B自动准备尚未接入该流程。

## 交互式添加

```bash
./setup.sh --server-dir /srv/minecraft
# 也可直接运行setup.sh，选择“9”
```

确认方案后，准备项目内Python、下载工具、需要时编译llama.cpp、匹配客户端/Java、ASM SDK、模型下载/转换/校验，设置目标、角色名、长期笔记与自动整理间隔。后台输入和只读采集器在启动检查中构建和验证。

缺失系统依赖时先显示安装命令，再询问是否执行；可能需要sudo。不会安装/替换显卡驱动或自动升级发行版。GPU编译需要已有CUDA工具链；缺少时可选择CPU模式或先提供兼容引擎。

### 方式1：只连接已有服务器（默认）

保留原server.properties、难度、世界、白名单、认证和启动脚本。服务器由原有方式运行，AI作为独立离线角色加入。工具的stop.sh只停止本项目客户端/模型/界面，不停止原服；此模式不启用管理命令，不自动应用和平/死亡不掉落。

在线认证尚未接入。向导会指出online-mode限制，不自动关闭认证；需要使用已授权的离线测试服。白名单应由服主允许所选AI角色。插件服务器可尝试使用对应原版客户端，自定义行为仍需验证。

### 方式2：创建独立托管副本

必须先停止原服，避免复制仍在写入的世界。选择服务端JAR、额外JVM参数和新端口；启动时复制到项目instances/deployed/，原件不改。副本才由工具管理启停并应用测试设置。

Forge/Fabric/NeoForge等服务器必须提供匹配的完整客户端清单、JAR和libraries/assets；不会因基础版本相同就下载原版冒充匹配客户端。模组与启动器自定义流程仍可能需要额外适配。

## 保存、重试和记忆

每个新实例有独立world_id、角色、目标、记忆和动作目录。默认重复使用同一实例ID与同一服务器时保留world_id；用同一ID改连另一服务器或改变托管方式会拒绝，避免旧记忆混用。更换世界也应使用新实例ID。

配置在local-instances.json，步骤记录在runtime/deployments/，均为本地私有文件。模型、客户端下载可重跑；日志会标记准备中、已配置或失败原因。重新运行向导可沿用下载结果；不会因为显示了“已配置”就声称游戏已经连接，仍需完整启动验收。

文档记忆将已观测位置/物品与模型建议分开。启动读取文档；模型进程的上下文本身不跨进程保存。仅接入模式的原服世界不在AI完整快照中，原服应按原有停服备份方式保存；避免把仍在运行的原服世界当成一致快照。
